# 0031 어댑터 송출 실패는 같은 이벤트 재시도로만 회복, ws 상한은 pause·1008 혼합

- 상태: 제안
- 날짜: 2026-10-04
- 결정한 사람: 작업자(제안)
- 관련: TASKS T11.H, 실험 노트 experiments/client-raster.md, FEEDBACK F-204·F-200

## 맥락
어댑터의 emit 이 던지면 그 메시지가 실제로 나갔는지 알 수 없다. 다른 이벤트가 이어지면 같은 pieceSeq 가 다른 key 로 나가거나 resume 이 막힌다.

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| (a) 쓴 순번까지 확정해 다음 이벤트는 새 순번 | 호출자가 단순 | 나가지 않은 메시지는 빈칸, 나갔다면 중복 가능 | 어댑터는 실제 송출 여부를 모름 |
| (b) 미완 이벤트를 기억, 다른 이벤트는 UnfinishedEventError, 같은 이벤트 재시도로 회복 | 순번이 원래 key 에 묶임, resume 멱등(F-197)과 맞물림 | 호출자가 재시도 책임 | 시험 6지점×5이벤트 |
| ws 미결 핸들러 상한: 1008 | 구현 단순 | 정상 폭주 연결을 끊음 | |
| ws 미결 핸들러 상한: pause | 정상 폭주를 견딤 | 끝나지 않는 핸들러는 그 연결만 정지 | 시험 |

## 결정
어댑터는 (b). ws 미결 핸들러는 pause(기본 64), send 버퍼 초과는 1008(기본 32 MiB).

## 근거
experiments/client-raster.md 참조.

## 대가
호출자(ws 배선)가 UNFINISHED_EVENT 를 받으면 같은 이벤트를 다시 넣어야 한다. 기본값 64·32 MiB 는 근거 없는 추정값이다.
