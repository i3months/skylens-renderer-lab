# 0043 S6 구간당 바이트: codec 1 + 구간 바이트 예산 안의 공간 균일 솎기

- 상태: 승인(조건부 — S6·S9 충돌은 사람 판단, F-302)
- 날짜: 2026-10-04
- 결정한 사람: 작업자(제안)
- 관련: TASKS T13.B, FEEDBACK F-292, 결정 0027(codec 1)·0042 §3(S6 미달 기록), 실험 노트 [experiments/t13b-s6.md](../experiments/t13b-s6.md)

## 맥락
SPEC §4 S6 구간당 ≤ 3,000,000 B(MB = 10^6 B, 한 구간 4수준 전체의 웹소켓 프레임 바이트 합)가 구간당 250만 점 합성에서 51.6 MB(17.2배)로 미달이었다(0042 §3). 원인은 둘이다. ① 측정 경로가 codec 0(무압축 평면, 11 B/점)을 보냈다. ② 4수준을 모두 보내 점 합이 최고 수준의 1.875배다. 0042 §3 의 다시 볼 조건대로 T13.B 에서 large 구간당 ≤ 3,000,000 B 단언을 넣어야 한다. 문턱은 바꾸지 않는다.

## 선택지
측정은 모두 SPEC 규모(최고 수준 250만 점, seed 1)의 실제 프레임 길이다. 표의 수치는 실험 노트에서 옮겼다.

## 결정
codec 1(무손실 색)로 부호화하고, 구간 4수준 프레임 바이트 합이 3,000,000 B 를 넘으면 수준마다 자기 점군을 모턴 순 공간 균일로 솎아(원본 수준 점 수 비 유지, 각 수준 최소 1 점) 실제 바이트가 3,000,000 B 이하가 되는 가장 큰 점 예산을 보낸다(B+C, A 는 기각).

## 근거
- SPEC 규모 측정(`measureStatusBandwidth({segments:3, pointsPerSegment:2500000, ...S6_SEND_CONFIG})`): 구간당 2,929,312 / 2,925,801 / 2,924,359 B(문턱의 97.5~97.6%), 송출 점 628,069 / 628,578 / 628,279(원본 4,687,500 의 13.4%), 최고 수준 약 33.5만 점. 초기 225,209 B.
- 솎기 없이 도달할 수 있는 최소값은 A+C 10.0 MB(3.3배, 그러나 A 는 규칙 충돌), A 없이 C 17.4 MB(5.8배)다. **솎기 없이는 S6 구간당 문턱을 만족할 수 없다.** 필요한 점 예산은 codec 1·공간 균일 기준 구간 4수준 합 약 63만 점(최고 수준 약 33.5만 점)이다(합성 장면 측정, 실자산은 추정 불가).
- 예산 맞춤은 숫자를 추정하지 않고 실제 송출 경로(조각 분할·codec 1·PIECE·LEVEL_ARRIVED 프레임)로 잰 바이트로만 판정한다(`server/scheduler/segment_budget` fitSegmentBudget, 시도 2회).
- 제품: `bench/status_bw/s6_segment.test.mjs` 가 구간당 ≤ 3_000_000 B(숫자 리터럴)를 SPEC 규모에서 단언하고 통과한다(9.2 s). 측정 명령·수치는 실험 노트.

## 대가
- **화질 영향이 있다.** 최고 수준 점이 원본의 약 13.4% 로 줄어 점 간격이 약 2.7배(√(1/0.134), 추정) 넓어진다. 시점 SSIM 은 bench/status_quality 에서 따로 잰다. S9(SSIM ≥ 0.95)를 해칠 수 있다. **측정됨**([t13b-quality.md](../experiments/t13b-quality.md)): 이전 20만·100만 점 값(무작위·3D 격자 솎기, 채택 방식 아님)은 솎기 50% 부터 SSIM 최소 0.56~0.86 으로 0.95 미달이다. 채택 방식(모턴 등간격·수준 비례, 구간 예산이 정한 13.40%)을 250만 점에서 8시점 그대로 잰 값은 SSIM 최소 0.6877·평균 0.7534 로 0.95 미달이다(50% 도 최소 0.8714). 즉 S6 을 맞추면 S9 와 충돌한다. 이 충돌은 사람이 판단한다(F-302). 합성 flat_boxes 단일 장면 기준이다.
- **SPEC §2 Δd 기반 LOD 원칙에서 벗어난다.** SPEC §2(Δd ≈ d_c²/(f·b))는 LOD 를 원본 정밀도 Δd 와 시점 거리별 화면 픽셀 크기로 정하라고 한다. 이 솎기는 시점·Δd 와 무관하게 구간 바이트(3,000,000 B)만 기준으로 모턴 순에서 등간격으로 점을 덜어 낸다(renderer_basis 의 Δd 근거를 쓰지 않음). 이유: S6 은 시점과 무관한 구간 총 바이트 문턱이고, 솎기 없이는 최소 10.0 MB(A+C)라 어떤 Δd 기준 LOD 도 구간 송출 점 수를 이 문턱까지 내린다고 보장하지 못한다. 시점별 LOD 선택(TAU=0.5)은 그대로 두고 그 앞 단계에서 송출 점군만 줄인다. 대가로 Δd 보다 촘촘한 곳과 성긴 곳을 가리지 않고 깎아 화질이 떨어진다(바로 위 항목). Δd 를 쓰는 솎기(밀도가 Δd 보다 촘촘한 곳부터 덜기)는 측정하지 않았고 다시 볼 조건에 올린다.
- 보내지 않은 점은 화면에 없다. 클라이언트가 점 크기를 키우는 등의 보완은 이 결정 밖이며, 없는 점을 메우거나 보간하지 않는다.
- 점 예산이 자산의 B/점에 따라 달라진다. 실자산 B/점이 합성보다 크면(codec.md: 잡음 큰 지형 1만 점 7.33 B/점) 보내는 점이 더 줄어든다.
- 예산 맞춤에 구간마다 부호화를 여러 번 한다(합성 250만 점 구간에서 시도 2회, 구간당 약 3 s, 오프라인 일괄 처리 가정).
- 같은 바이트에서 최고 수준 화면 점 수를 약 1.9배로 늘릴 수 있는 A 를 포기했다(규칙 충돌 때문).
- 실제 송출 경로(코어가 넘기는 .skla 조각을 만드는 자산 처리 서버)에 예산을 거는 배선은 아직 없다. 어댑터는 조각 내용을 해석하지 않는다.
- 기존 status_bw.test.mjs 의 회귀 상한 시험(0042 §3)은 다른 작업자 소유라 지우지 않았다(T13 기준 구성 측정으로 남아 있음). 지울지는 감독 판단.

## 다시 볼 조건
- Δd 를 쓰는 솎기(SPEC §2 원칙과 맞는 방식)가 같은 바이트에서 SSIM 을 올리는지 잰다.
- bench/status_quality 의 시점 SSIM 이 S9(0.95) 미만이면: 중요도 솎기, 수준별 몫 조정(최고 수준에 더 주기), 압축률 개선(위치 차분 모델 등)을 다시 잰다. 그래도 안 되면 S6 과 S9 의 충돌을 측정값과 함께 FEEDBACK 에 올린다(문턱은 낮추지 않음).
- 실자산 B/점·4수준 관계를 [local] 에서 잰 결과 4수준이 실제로 포함 관계이면 A(증분)를 규칙과 함께 다시 본다.
- codec 1 개선이나 새 codec 으로 B/점이 크게 줄면 예산 맞춤이 자동으로 점을 더 보낸다(구성 변경 불필요). 그때 솎기 없이 문턱 안에 드는지 다시 잰다.

## 추가 측정 (압축만으로의 한도)
[t13b-codec.md](../experiments/t13b-codec.md): 화질 S9 를 지키는 손실 조합으로도 압축만으로는 250만 점 구간이 합성 12.6 MB(어려운 변형 16.0 MB)까지만 내려가 3 MB 에 닿지 않는다. 3 MB 에는 구간 점 예산이 어떤 경우에도 필요하다(4수준 합 기준 최고 수준 점 약 41만~51만). 위치 정밀도를 거칠게 하면 대역폭은 맞지만 SSIM 이 0.66~0.71 이다. 따라서 S6 과 S9 의 충돌 가능성은 압축으로 풀리지 않는다.
