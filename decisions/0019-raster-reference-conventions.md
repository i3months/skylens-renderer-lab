## 맥락
T06 의 모든 모듈(투영·역투영·스플랫·z-버퍼·셰이딩·지표)이 같은 규약을 써야 한다. 계약(제품 contracts/raster)에서 아래를 정했다.

## 선택지
| 항목 | 선택지 | 비고 |
|---|---|---|
| 카메라 규약 | (가) OpenCV: x 오른쪽, y 아래, z 앞 / (나) GL: y 위, −z 앞 | renderer_basis §2 가 d = X_c.z, [u,v,1]ᵀ ∝ K·X_c 이므로 (가). GL 시점은 diag(1,−1,−1) 로 변환(tools/render_views) |
| 픽셀 좌표 | (가) 정수 좌표 = 칸의 왼쪽 위 모서리, 중심 = i+0.5 / (나) 정수 좌표 = 칸 중심 | 합성 장면 미리보기(T05)가 (가) 를 이미 씀 |
| K 환산 | (가) 단순 배율(cx·s) / (나) 반 픽셀 보정((cx+0.5)s−0.5) | renderer_basis §1-2 의 960 px K 가 (가). 옵션 pixelCenter 로 둘 다 지원, 기본 (가) |
| 빈 픽셀 | depth 0, index −1, color (0,0,0) | 메우지 않는다(skylens 원칙). 같은 깊이는 먼저 온 점이 이긴다 |
| 스플랫 크기 | 반경 r = fx·sizeM/(2d) 픽셀(거리 반비례), 중심이 반경 이내(≤)인 픽셀, 점이 속한 칸은 항상 포함 | |

## 결정
위 표의 첫 번째 선택(K 환산은 (가) 기본, (나) 는 옵션).

## 근거
- renderer_basis §2-3 예제: 문서의 X_c=(−5.03,−7.84,45.28)(소수 둘째 자리 반올림)로 직접 계산하면 u=396.2052, v=139.4747 로, 문서 픽셀 (396.27, 139.47) 과 u 가 0.065 px 어긋난다. 문서 값에서 거꾸로 푼 X_c.x=−5.02611(반올림하면 −5.03)로는 396.27 을 0.01 px 이내로 재현한다. 따라서 "0.01 px 이내" 기준은 반올림 전 좌표 기준으로 시험하고(project·unproject 시험 둘 다), 반올림된 X_c 에 대해서는 반올림 오차 한계(0.083 px) 이내로만 확인한다. 기준을 낮춘 것이 아니라 문서 예제 입력이 반올림된 값이라는 사실을 시험에 박은 것이다. 독립 서브에이전트 2개가 같은 결과를 얻었다.
- K 환산 2048×1152→960×540: fx 754.321875, fy 753.8484375, cx 480, cy 270(단순 배율); 반 픽셀 보정은 cx 479.734375, cy 269.734375(차 0.5(s−1) px).
