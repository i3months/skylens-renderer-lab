# 0001 두 경로(B 자산 경량화, A 픽셀 스트리밍)와 화면별 배정

- 상태: 승인
- 날짜: 2026-10-01
- 결정한 사람: 사람
- 관련: SPEC §목표, TASKS 1단계·2단계

## 맥락
skylens 의 3D 표시를 클라이언트 렌더링에서 서버 쪽으로 옮긴다. "서버 렌더링"은 서버가 픽셀을 그려 보내는 방식과, 서버가 무거운 가공을 맡고 클라이언트는 가볍게 그리는 방식 두 가지로 해석된다.

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| A 픽셀 스트리밍만 | 클라이언트 3D 코드 0 | 접속자 수에 비례해 서버 GPU 필요(지휘관 30명), 왕복 지연이 조작에 직결 | skylens current_doc ARCH-02 §5-1 (지휘관 30명) |
| B 자산 경량화만 | 가공 1회, 조작이 로컬이라 지연 없음 | 클라이언트에 3D 코드가 남음 | — |
| A+B 혼합 | 화면 성격에 맞춰 고름 | 두 경로를 다 만들어야 함 | — |

## 결정
A+B 혼합. 관제탑은 B 고정, 현황판은 저사양·모바일 A / 고사양 B.

## 근거
- 관제탑은 방향키 조향·Q/E 고도·드론 전환이 있어 왕복 지연이 조작감에 그대로 얹힌다. 그래서 A 를 쓰지 않는다.
- 현황판은 지휘관이 주로 보는 화면이라 저사양 기기에는 A 가 맞다.
- 기기 사양 분기를 현황판 안으로 한정해 테스트 조합을 3개(관제탑 B, 현황판 A, 현황판 B)로 줄였다.

## 대가
두 경로 구현 비용. 현황판 A 경로는 GPU 서버가 필요하다(0004).

## 다시 볼 조건
- 현황판 A 의 왕복 지연이 SPEC 의 입력→화면 기준(A 150 ms)을 넘으면 현황판도 B 로 통일을 검토한다.
- 관제탑에 저사양 기기 요구가 생기면 관제탑 A 를 다시 검토한다.
