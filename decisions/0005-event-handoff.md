# 0005 이벤트 핸드오프와 예비 시간표, 역할당 루틴 1개

- 상태: 승인
- 날짜: 2026-10-01
- 결정한 사람: 사람
- 관련: ops/WORKER.md, ops/SUPERVISOR.md

## 맥락
작업자와 감독을 어떻게 깨울지. 루틴 하나의 시간 트리거는 최소 1시간 간격이다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 시간표만(역할당 루틴 2개로 30분 주기) | 단순 | 앞 일이 끝나도 다음 정시까지 대기 |
| 이벤트 + 예비 시간표(역할당 1개) | 끝나자마자 다음 역할이 깨어남 | 이벤트 누락 시 최대 1시간 공백 |

## 결정
이벤트 + 예비 시간표. 감독은 제품 PR 에 라벨이 붙으면, 작업자는 제품 PR 이 닫히면(병합·반려) 깨어난다. 예비로 작업자 매시 :05, 감독 매시 :20. 차례 판정은 STATUS 상태 줄 하나로만 한다.

## 근거
- 2026-10-01 실측: 라벨 → 감독 기동 4초, 2초.
- 루틴 GitHub 트리거가 지원하는 이벤트는 PR·Release 뿐이라 PR 댓글로는 작업자를 깨울 수 없다(공식 문서 Routines). 그래서 반려도 "PR 닫기"로 신호한다.
- 브랜치 푸시 시각으로 차례를 판정하던 방식은 앞 작업자의 마지막 푸시를 다른 작업자로 오인해 20분을 날렸다(2026-10-01). 그래서 STATUS 하나로 바꿨다.

## 대가
이벤트가 누락되면 최대 1시간 멈춘다. 같은 역할이 겹쳐 뜰 수 있어 STATUS 15분 규칙에 의존한다.
