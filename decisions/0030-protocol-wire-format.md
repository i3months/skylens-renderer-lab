# 0030 웹소켓 프로토콜: 8 B 머리 + 고정 배치 본문, 검사 순서를 서버·클라이언트가 공유

- 상태: 제안
- 날짜: 2026-10-04
- 결정한 사람: 작업자(제안)
- 관련: TASKS T11, 실험 노트 experiments/protocol.md, SPEC §7(웹소켓 단일)·S6(대역폭)

## 맥락
SPEC §7 은 웹소켓(TCP) 단일 규약을 정하고 렌더러가 그 위에 메시지 종류를 더한다고 한다. 서버·클라이언트 복호가 다른 순서로 검사하면 같은 깨진 프레임에 다른 오류가 나 교차 시험이 불가능하다(F-176·F-182 에서 codec 이 겪은 문제).

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| A. 이진 프레임: 머리 8 B(type·version·reserved·길이) + 종류별 고정 배치, 검사 순서를 계약에 고정 | 복호가 단순, 조각 바이트를 복사 없이 실을 수 있다 | 종류를 늘리면 version 을 올려야 함 | 교차 시험 1,000 입력 일치(노트) |
| B. JSON 텍스트 프레임 + 조각은 별도 | 사람이 읽기 쉽다 | 조각 바이트 base64 로 +33 %(S6 구간당 ≤ 3 MB 를 잠식) | 산식 4/3 |
| C. protobuf 류 외부 라이브러리 | 스키마 도구 | 의존성 추가, 퍼징 표면 | 기각(의존성 없음 규칙) |

## 결정
A. 방향 검사는 프레임 길이 검사 뒤, 고정 크기 검사 앞(서버·클라이언트 같음). 조각 요청 항목 ≤ 256, 본문 ≤ 4 MiB(F-175 ⑥).

## 근거
교차 시험이 처음에는 방향 검사 위치(클라이언트가 type 직후)와 중복 키 거부(클라이언트만)에서 어긋났고, 계약에 순서를 적고 클라이언트를 서버에 맞춰 일치시켰다(노트).

## 대가
메시지 종류 추가 때 version 올림. 본문 상한 4 MiB 는 임의값이며 T12 에서 조각 크기 분포로 다시 본다(근거 없음, 추정).

## 다시 볼 조건
실제 skylens `ws` 경로와 합치는 단계(T11.8 의 가정이 원본과 다를 때), 조각이 4 MiB 를 넘을 때.
