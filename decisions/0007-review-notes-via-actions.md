# 0007 감독 판정은 검토 노트 파일 → Actions 봇이 게시

- 상태: 승인
- 날짜: 2026-10-02
- 결정한 사람: 사람
- 관련: 제품 .github/workflows/post-review.yml, reviews/

## 맥락
클라우드 세션이 GitHub 에 글을 새로 만들면 연결 앱 배지가 붙고, 본문 끝에 생성 도구 문구가 자동으로 붙어 수정 기록에 남는다(2026-10-01 PR #2 댓글·본문 수정 기록에서 확인). 댓글 자체는 남기고 싶지만 그 표시는 없어야 한다.

## 선택지
| 선택지 | 작성자 표시 | 비고 |
|---|---|---|
| 감독이 직접 댓글 | i3months + 연결 앱 배지 | 생성 도구 문구가 수정 기록에 남음 |
| 개인 토큰으로 게시 | i3months | 문구가 안 붙는지 미검증, 토큰을 클라우드에 맡겨야 함 |
| Actions 봇이 게시 | github-actions[bot] | 확실히 동작(2026-10-02 시험) |
| 댓글 없음 | — | PR 화면에 판정이 안 보임 |

## 결정
감독은 판정마다 reviews/pr-<번호>.md 를 커밋하고 PR 을 닫거나 병합한다. 제품 저장소 Actions 가 PR 이 닫힐 때 그 파일을 읽어 댓글로 올린다. 첫 줄 '감독 검토 #k (PR #n) — 통과|반려' 로 중복을 막는다.

## 근거
- 2026-10-02 시험: 게시 성공(작성자 github-actions[bot], 앱 배지·문구 없음), 같은 노트 재실행 시 "Already posted" 로 건너뜀.

## 대가
작성자가 사람 이름이 아니라 봇으로 보인다. 작업자가 PR 을 새로 열 때 본문 첫 판의 문구는 여전히 생긴다(사람이 수정 기록에서 지운다).

## 다시 볼 조건
클라우드 세션의 attribution 설정이 다중 저장소 세션에서도 먹게 되면 직접 게시로 되돌리는 것을 검토한다.
