# 0009 T02 스택 선정

- 상태: 제안
- 날짜: 2026-10-01
- 결정한 사람: 작업자(제안). 감독 승인 대기.
- 관련: T02, 연구 experiment/stack 의 experiments/stack/decision.md 와 조사 노트 10건

## 맥락
자산 처리 서버·클라이언트 경량 래스터라이저·2단계 서버 래스터라이저·인코더의 언어와 기술을 정해야 T03 이후를 시작할 수 있다.

## 제안 요약
| 항목 | 제안 |
|---|---|
| 자산 처리 서버(1단계) | Node.js 22 (ESM), 무거운 루프는 worker_threads, 병목이 측정되면 그 루프만 네이티브로 |
| 클라이언트 래스터라이저(B) | WebGL2, three.js 최소 구성에서 시작 |
| 서버 래스터라이저(2단계 A) | 확정하지 않음. 1순위 헤드리스 Chromium, 2순위 wgpu(Rust) 또는 Dawn |
| 인코더(2단계 A) | 하드웨어 인코더 추상화(NVENC 우선), FFmpeg 는 LGPL 빌드만 |

## 근거(제안 노트에서 옮김)
- 같은 알고리즘(100만 점 투영 + 1280×720 z버퍼, 단일 스레드, 클라우드 4코어) 측정: C++ 20.9~25.2 ms, Go 22.7~23.6 ms, Rust 25.0~31.7 ms, Node 37.9~49.4 ms, Python+numpy 178~252 ms.
- 1단계 서버 가공은 오프라인 일괄 처리라 Node 의 약 1.6~2배 차이가 화면 속도에 직접 영향을 주지 않는다는 판단.
- 서버·클라이언트가 양자화·식별자·체크섬·수준 상태를 같은 코드로 공유할 수 있다. skylens 도 TypeScript 다.

## 알려진 위험(제안 노트에 기록됨)
- Node 는 f64 로 계산해 다른 언어와 화면 픽셀 수가 5개 달랐다. 결정적 출력 규칙이 필요하다.
- 병렬 처리·실제 LOD·코덱 루프·67 MB 입출력 속도는 미측정.

## 사람의 의견(2026-10-02)
사람은 Rust 여부를 물었고, 근거를 확인한 뒤 제안을 존중해 바꾸지 않기로 했다. 다만 2단계 서버 래스터라이저는 wgpu(Rust)가 유력하다는 의견이 있었다. 결정 근거를 빠짐없이 기록할 것을 요구했다.

- 2단계 [local] T20 실측(동시 30명) 뒤 서버 래스터라이저를 확정한다.

감독은 승인·기각할 때 이 파일의 상태와 근거를 갱신한다.
