# 결정 기록

기술적 결정은 모두 여기에 남긴다. 결정 하나에 파일 하나(`NNNN-짧은-이름.md`).
결정을 바꿀 때는 기존 파일을 고치지 않는다. 새 파일을 쓰고, 기존 파일의 상태를 `대체됨(→ NNNN)` 으로 바꾼다.

## 언제 쓰는가

- 언어·런타임·라이브러리·포맷·프로토콜·알고리즘을 고를 때
- 운영 방식(루틴·핸드오프·병합·모델 배정)을 정하거나 바꿀 때
- SPEC 의 수치·범위를 정하거나 바꿀 때
- renderer_basis.md 에서 벗어날 때
- 후보를 기각할 때(기각 이유도 결정이다)

## 누가 쓰는가

- 작업자: 결정이 필요한 곳에서 `상태: 제안` 으로 쓴다. 근거가 되는 실험 노트·측정값을 링크한다.
- 감독: 검토 때 `승인` 또는 `기각` 으로 바꾸고 승인 근거를 덧붙인다. 감독이 직접 내린 결정도 여기에 쓴다.
- 사람이 내린 결정은 `결정한 사람: 사람` 으로 적는다.

## 형식

```
# NNNN 제목

- 상태: 제안 | 승인 | 기각 | 대체됨(→ NNNN)
- 날짜: YYYY-MM-DD
- 결정한 사람: 사람 | 감독 | 작업자(제안)
- 관련: TASKS 작업 번호, 실험 노트, FEEDBACK 항목

## 맥락
무엇을 정해야 했고 왜 지금인가.

## 선택지
| 선택지 | 장점 | 단점 | 근거(측정·출처) |

## 결정
한 문장.

## 근거
측정한 수치와 출처. 추정은 "추정"으로 표시한다.

## 대가
이 결정으로 포기한 것, 감수하는 위험.

## 다시 볼 조건
어떤 측정·사건이 생기면 이 결정을 다시 검토하는가.
```
