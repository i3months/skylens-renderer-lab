# 0015 자산 포맷: 두 입력 형식을 한 포맷(.skla)에 담는다

- 상태: 승인
- 날짜: 2026-10-02
- 결정한 사람: 작업자(제안)
- 관련: T03 asset-format, 결정 0012(입력 두 형식), 제품 `format/ASSET_FORMAT.md`, 실험 노트 `experiments/asset-format.md`

## 맥락
T03 은 27 B 점과 56 B 가우시안을 모두 담는 경량 자산 포맷을 정해야 한다(0012). 0012 의 지침은 단일 포맷을 우선 검토하고 분리 포맷과 비교한 근거를 남기라는 것이다.

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| A. 한 포맷, 헤더의 형식 표시(1 = 점 27, 2 = 가우시안 56) + 공통 필드(위치·색) + 형식별 선택 평면 | 헤더·타일·LOD·수준 식별자·체크섬·검증기·퍼저·클라이언트 읽기 한 벌. 딜레이 패턴 수준 교체 규칙과 Δd 근거가 코드 경로 하나. 부 버전 확장 평면으로 고차 SH 등을 더할 수 있음 | 읽는 쪽이 형식 분기를 안다(평면 목록 표 하나) | 명세 §0·§4: 공통 평면 6개(위치 3 u16, 색 3 u8) 형식 1 은 +법선 2 i8 = 11 B/점, 형식 2 는 +opacity·scale 3·회전 u32 = 17 B/점 |
| B. 형식마다 별도 포맷 두 개 | 각 포맷이 단순 | 헤더·타일·식별자·검증·호환 정책 코드가 두 벌, 두 형식에서 규칙이 어긋날 위험, 서버 렌더러(2단계)가 입력 두 종을 따로 다룸 | 공통 필드가 위치·색으로 같고 타일·LOD·수준 규칙이 형식과 무관 |

## 결정
한 포맷을 쓴다(A). 형식 표시 1 바이트로 필수 평면 집합을 정하고, 공통 평면은 위치·색, 선택 평면은 형식별로 둔다.

## 근거
- 형식 간 다른 부분은 본문 평면 목록뿐이다. 헤더(128 B)·타일(ENU 64 m 격자)·구간/수준 식별자·체크섬·버전 정책은 같다.
- 본문 크기: 형식 1 은 원본 27 B 의 40.7%(11 B), 형식 2 는 56 B 의 30%(계산, 명세 §0). 분리해도 줄어드는 바이트는 없다(평면 배열은 같다).
- 골든 파일은 형식마다 1개(`fixtures/asset_golden/point27.skla`, `gauss56.skla`)로 두 경로를 모두 고정한다.
- 대가: 형식 분기 한 군데(`PLANES` 표). 다시 볼 조건: T09 압축이 형식별로 크게 갈릴 때(그때 codec 값으로 분기하거나 포맷을 나눈다).
