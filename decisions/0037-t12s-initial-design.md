# 0037 T12.S 초기 설계: 지연 경로, Worker 타임아웃 처리, 호출자 예외 처리

- 상태: 제안
- 날짜: 2026-10-04
- 결정한 사람: 작업자(제안)
- 관련: FEEDBACK F-248 ④, F-250 ①, 결정 0034, 결정 0036(5~7 이 시한·makeRoom 서술을 정정)

## 맥락

T12.S 구현에서 LEVEL_ARRIVED 도착 이벤트가 폭주할 때 선택 계산을 모든 도착 이벤트마다 하지 않고 프레임당 한 번으로 합치기 위해 지연 경로가 필요하다(F-248 ④). Worker 복호 타임아웃이 발생했을 때 막힌 Worker의 대기 중인 요청들을 어떻게 처리할 것인가. 호출자가 예외를 처리해야 하는 책임 경계를 정한다.

## 선택지

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A | 지연 경로도 호출 시점에 입력 검사하고 상태 기록만 함 | 예외가 즉시 드러남, 상태 일관성 | 호출자가 예외 처리 필요 |
| B | 지연 경로는 입력 검사 없음 | 호출자 예외 처리 불필요 | 검사를 draw로 미루고 오염 가능성 |

**선택 1: 호출자 예외 처리 - setArrived 지연 경로도 호출 시점에 입력 검사**: 지연 경로 호출자(도착 이벤트 핸드러)가 setArrived 의 'piece' 예외를 처리해야 한다. 하지만 잘못된 입력이 상태를 오염시키지 않는다. 검사는 O(key 수)로 합치기 목표와 상충하지 않는다.

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A | 타임아웃 시 막힌 Worker의 모든 대기 요청 즉시 거부(failAll) | 그 뒤 새 요청이 영구 대기하지 않음 | 일부 요청이 예외 대신 거부됨 |
| B | 타임아웃만 거부하고 뒤 요청은 계속 대기 | 간단함 | 한 번 막히면 이후 요청도 계속 막힘 |

**선택 2: Worker 타임아웃 시 failAll**: Worker 가 타임아웃된 요청을 처리 중이라고 보고, 그 시점의 모든 대기 중 요청을 즉시 거부한다. 시한이 지나면 Worker 클라이언트가 스스로 Worker 를 terminate 하고 terminated 플래그를 세워 이후 decode 는 즉시 거부한다. 새 Worker 를 만드는 것(재생성)만 호출자 몫이다(결정 0036 5).

| 선택지 | 설명 | 장점 | 단점 |
|---|---|---|---|
| A | makeRoom 에서 희생 선택 시마다 현재 선택을 재계산 | 새 도착에 맞춰 희생 갱신 | 계산 비용, 복잡도 증가 |
| B | makeRoom 에서 지금 올리는 key 만 선택에 포함, 나머지 희생은 도착 기반 | 희생 선택이 간단, 현재 업로드 key 보호 | 선택 상태는 바꾸지 않음 |

**선택 3: makeRoom 희생 선택 - 현재 업로드 key 포함 규칙**: 희생(evict)을 고르기 위해 현재 선택의 그리는 조각 집합(drawing set)을 먼저 구한다. 현재 올리는 key 가 도착 집합에 들고 아직 상주하지 않을 때는 (옛) 그 key 를 넣은 임시 선택(저장하지 않는 옛 방식)으로 이 집합을 구해(그 key 가 완성할 LOD 의 상주 조각이 draw 에 들어갈 것으로 보고) 희생에서 제외한다. 선택 상태(arrived·selection) 자체는 바꾸지 않으므로 다음 draw 에서 선택이 낡을 수 있으므로 주의가 필요하다. 다만 업로드가 실패하고 희생이 있었으면 selectionStale 을 세운다. 결정 0036 7(가)가 roomProtection 으로 이를 대체한다.

## 결정

1. **호출자 예외 처리**: setArrived 의 지연 경로도 호출 시점에 항목·key(형식, segmentId·level 일치, level 0..3)를 검사해 'piece' 예외를 던진다. 호출자(도착 이벤트 핸드러, 어댑터 경계)가 이를 처리해야 한다.

2. **Worker 타임아웃 처리**: 맨 앞 요청이 timeoutMs 안에 응답하지 않으면 그 요청과 그 시점의 대기 중 모든 요청을 즉시 거부한다(failAll). Worker 를 terminate 하고 terminated 플래그를 세워 이후 decode 호출은 즉시 'terminated' 오류로 거부한다. 새 Worker 를 만드는 것(재생성)은 호출자 몫이다.

3. **makeRoom 희생 선택 규칙**: 메모리 여유를 만들기 위해 희생을 선택할 때, 현재 올리는 key 와 현재 선택의 그리는 조각들을 제외한다(올리는 key 를 넣었을 때의 보호 집합 판정은 결정 0036 7(가)의 roomProtection 증분 판정). 선택 상태는 바꾸지 않는다(낡은 선택으로 유지, 업로드 실패 시 희생이 있었으면 selectionStale).

## 근거

- **지연 경로 검사**: 합치기의 목표는 고빈도 도착 이벤트를 프레임당 1회로 줄이는 것. 입력 검사는 O(key 수) 비용으로 목표와 상충하지 않고, 호출자는 어댑터 경계에서 예외를 한 번만 처리한다.
- **failAll**: Worker 타임아웃은 전체 복호 루프가 막혔다는 신호. 그 뒤 요청을 계속 대기하면 영구 미결 상태가 되므로, 막힌 시점의 모든 요청을 거부하고 Worker 를 terminate 해 연쇄 오탐을 방지한다.
- **makeRoom 규칙**: 메모리 한도를 지키면서도 현재 업로드 중인 key 를 보호해 그것의 완성이 막히지 않게 한다. 선택 상태는 변경하지 않으므로 다음 draw 에서 업데이트를 기다린다.

## 대가

- **호출자 예외 처리**: 도착 이벤트 핸드러가 'piece' 예외를 try-catch 로 처리해야 한다. 하지만 검사가 호출 시점에 일어나므로 상태 일관성을 보장한다.
- **Worker 타임아웃 실패**: 일부 요청이 예외 대신 timeout 오류로 거부된다. 호출자가 Worker 를 재생성해야 한다.
- **makeRoom 선택 비갱신**: 선택이 낡으면 일부 pending/discard 조각의 분류가 달라질 수 있다. 다음 draw 의 선택 갱신으로 해결된다.

## 다시 볼 조건

1. 호출자(ws 핸드오프, F-238 ④)가 도착 이벤트 도중에 key 검사 결과가 필요하면 'piece' 예외 대신 검사 전용 메서드를 만들고 다시 본다.
2. Worker 타임아웃이 실제 운영에서 문제가 되면 timeoutMs 튜닝 또는 failAll 정책을 검토한다.
