# 0029 수준(levels) 상태 기계: 도착 이벤트만으로 갱신, 교체·건너뛰기 규칙을 계약 함수로 고정

- 상태: 제안
- 날짜: 2026-10-04
- 결정한 사람: 작업자(제안)
- 관련: TASKS T10, 실험 노트 experiments/levels.md, SPEC §3(딜레이 패턴 4수준)

## 맥락
SPEC §3 은 수준 250/1,000/3,500/7,000 에서 새 수준이 같은 구간의 낮은 수준을 교체하고 추월당한 수준은 건너뛰라고 한다. 서버와 클라이언트가 같은 규칙을 따라야 하는데, 규칙이 두 구현에 흩어지면 어긋난다.

## 선택지
| 선택지 | 장점 | 단점 | 근거 |
|---|---|---|---|
| A. 규칙 한 함수(`decideArrival`)를 계약에 두고 서버·클라이언트 기계가 각자 구현하되 그 함수만 공유 | 규칙 단일 출처, 클라이언트가 server/ 를 import 하지 않음 | 기계 본체는 두 벌 | 입력 열 1만 개 동등성 시험으로 일치 확인 |
| B. 기계 전체를 계약 모듈에 두고 공유 | 코드 한 벌 | 클라이언트 번들이 서버 코드에 묶임 | 기각 |
| C. 도착 시각(타이머)으로 수준을 올림 | 없음 | skylens 원칙(도착한 것만, 추월 건너뛰기)과 충돌 | 기각 |

## 결정
A. 상태는 도착 이벤트(`arrive`)와 `expect` 로만 바뀌고 시계·타이머를 쓰지 않는다. 같은 수준의 재도착은 추월당한 것으로 보고 건너뛴다.

## 근거
- 같은 수준 재도착을 skip 으로 보는 것은 "도착 수준 ≤ 현재 수준이면 건너뜀"(SPEC §3 '추월당한 수준은 건너뛴다')을 문자 그대로 옮긴 것이다. skylens 원본 splatScene.ts 가 같은 수준 재도착을 어떻게 다루는지는 이 환경에서 원본을 읽지 못해 **확인하지 못했다**(server/levels/parity/UNVERIFIED.txt). 추정.
- 4수준 전 순열 24가지, 무작위 10만 열 불변식 시험(T10.8)으로 단조성·교체 시 누적 0 확인.

## 대가
원본 동작과의 일치는 문서에 있는 서술 범위(16건)까지만 확인했다. [local] 원본 소스 대조가 남았다.

## 다시 볼 조건
skylens 원본 splatScene.ts 를 읽을 수 있게 되어 같은 수준 재도착·건너뛰기 이벤트 처리가 다르다고 드러날 때.
