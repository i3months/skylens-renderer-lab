# T13.B S6 구간당 바이트 — 실험 노트

- 제품 feat/t13b--7(커밋 0cb8308f), 연구 experiment/t13b. 관련: TASKS T13.B, FEEDBACK F-292, 결정 [0043](../decisions/0043-t13b-s6-codec1-spatial-budget.md), 앞선 기록 [t13.md](t13.md)·[0042](../decisions/0042-t13-wire-and-bandwidth-records.md) §3.
- 문턱: SPEC §4 S6 구간당 ≤ 3,000,000 B(MB = 10^6 B), 초기 ≤ 15,000,000 B. 문턱은 바꾸지 않았다.

## 출발점
- `measureStatusBandwidth({segments:3, pointsPerSegment:2500000})`(T13 구성: codec 0 무압축 평면 .skla, 4수준 전부): 구간당 51,602,140 / 51,603,260 / 51,602,792 B, 초기 3,440,198 B.
- 점당 11.01 B(위치 u16×3 + 색 u8×3 + 법선 팔면체 i8×2 = 11 B, 27 B 원본 대비 2.45배). 4수준 점 합 4,687,500 = 최고 수준 2,500,000 × 1.875.
- 알게 된 것: 이 측정 경로는 codec 1(SKLC1, 결정 0027)을 거치지 않고 codec 0 을 그대로 보내고 있었다. 클라이언트(client/codec)는 codec 1 을 이미 복호한다.

## 측정 방법
- 선택지 비교: 임시 스크립트(세션 scratchpad `exp.mjs`, 제품에 넣지 않음)로 levels 합성 장면(seed 1, 구간 1개, 최고 수준 250만 점)을 bench/proto `packCloudPieces`(64 m 타일, 조각 최대 2만 점) → [codec 1 `encodeChunk`] → `encodeMessage` → `encodeFrame` 실제 길이로 쟀다. 구간 바이트 = PIECE 프레임 합 + LEVEL_ARRIVED 프레임 4개.
- 250만 점 합성은 구성당 1~8 s 라 외삽 없이 SPEC 규모로 직접 쟀다.
- 최종 구성은 제품 `measureStatusBandwidth({segments:3, pointsPerSegment:2500000, ...S6_SEND_CONFIG})` 로 쟀다.
- 솎기 방식 이름: 균일(stride) = 수준 점군의 원래 순서에서 등간격(이 합성 장면은 생성 순서가 공간적으로 무작위라 사실상 무작위 표본), 공간 균일(spatial) = 모턴 순 등간격, 중요도(importance) = 모턴 이웃과의 색 차가 큰 점부터.
- '모턴 순 조각' = 점을 모턴 순으로 늘어놓은 뒤 2만 점 조각으로 자른 것. '원래 순서 조각' = 수준 점군 순서 그대로 자른 것.

읽은 것:
- 솎지 않는 조합 중 가장 작은 것은 A+C(모턴 순 조각) 10.0 MB 로 문턱의 3.3배다. 솎기(B) 없이는 3 MB 에 못 미친다. A 를 빼면 C(모턴 순 조각) 17.4 MB(5.8배)가 최소다.
- codec 1 은 조각이 공간적으로 모일수록 작다(같은 점 집합에서 원래 순서 5.30 → 모턴 순 3.72 B/점). 솎은 뒤에는 점 간격이 커져 4.6~4.7 B/점이다.
- 손실 색은 이 합성 장면(색 잡음 0..15)에서 오히려 커졌다(6.06 > 5.30 B/점). 쓰지 않는다.
- 3 MB 안에 넣으려면 codec 1·공간 균일에서 구간 4수준 합 약 63만 점(최고 수준 약 33.5만 점, 원본의 13.4%)이 상한이다. codec 0 이면 약 27만 점(최고 수준 약 14만 점)이다.
- 중요도 솎기는 같은 점 수에서 약 4% 작지만 점이 색 경계에 몰린다. A+B+C 는 같은 바이트에 비슷한 점 수(약 64만)를 보내되 최고 수준 화면에는 증분 합(약 64만 점)이 보이므로 화면 점 수는 B+C(약 33.5만)의 약 1.9배다 — 다만 규칙과 충돌한다(결정 0043 선택지 표).

## 최종 구성(결정 0043)과 SPEC 규모 측정
- 구성 `S6_SEND_CONFIG = {codec: 1, segmentByteBudget: 3_000_000}`: 수준마다 자기 점군을 모턴 순 공간 균일로 솎고(원본 점의 부분집합, 점 수는 원본 수준 비 유지), 모턴 순으로 조각을 자르고, codec 1(무손실 색)로 부호화한다. 점 예산은 `server/scheduler/segment_budget` 의 `fitSegmentBudget` 이 실제 프레임 바이트를 재 가며 정한다(시작 추정 5 B/점, 안전 계수 0.98, 허용 오차 5%).
- 명령: `node bench/status_bw/cli.mjs`(16.8 s, result.json 의 `s6`), `node --test bench/status_bw/s6_segment.test.mjs`(9.2 s).

## 이탈·미해결
- renderer_basis 이탈 없음: 27 B 형식·좌표(ENU)·법선·색 의미를 바꾸지 않았고, 보낸 점은 원본 점의 부분집합이다(양자화는 .skla 기존 규칙). 27 B 형식에는 신뢰도 필드가 없고 추가하지 않았다.
- 화질 영향은 재지 않았다(bench/status_quality 는 다른 작업자). 최고 수준 점이 원본의 13.4% 라 시점 SSIM 하락이 예상된다(추정).
- 실제 송출 경로(코어가 넘기는 .skla 조각)에 예산을 거는 배선은 없다. 어댑터는 조각 내용을 해석하지 않으므로 조각을 만드는 쪽(자산 처리 서버)이 `fitSegmentBudget` 을 써야 한다. 조립은 남음.
- 실자산 B/점(codec.md: 잡음 큰 지형 1만 점 7.33 B/점)이 합성보다 크면 예산 맞춤이 점 수를 더 줄인다. 실자산 측정은 [local].
