# T09 codec — 실험 노트

제품 브랜치 feat/codec. 결정: [0027](../decisions/0027-codec1-sklc1.md). 같은 PR 에 F-166(중간)·F-167(낮음) 처리를 포함했다.
모델별 서브에이전트: opus 4(T09.1·.2·.4·.5), sonnet 5(T09.3·.6·F-166 시험·T09.10·T09.11 시험)+2차 sonnet 2(T09.8·결함 수정), haiku 6(F-166 문구·F-167 3건·T09.7·T09.9). 승격 없음.

## 가설
양자화 값(§5)을 바꾸지 않고 모턴 재배치 + 필드별 차분 스트림 + 적응형 범위 부호화만으로 본문이 11 B/점보다 작아지고, §8 오차 상한과 화질(SSIM ≥ 0.98)이 유지된다.

## 방법
- 형식: format/ASSET_FORMAT.md §4.3, contracts/codec/index.mjs. 파이프라인 server/codec/chunk/ (encodeChunk·decodeChunk), 클라이언트 복호기 client/codec/.
- 시험 명령: `node --test <파일>` (Node 22 는 디렉터리 인자를 못 받음), 전체 `npm test`.

## 결론
- 위치·법선·색 오차 상한과 바이트 감소는 합성 데이터에서 충족했다. 1천 점 안팎의 작은 조각은 헤더·모델 적응 비용 때문에 이득이 작다(10.5 B/점).
- ~~미달 1건~~ → 결정 0028 로 해결(위 보정 절). 원래 기록: holes 장면(y=0 평면 한 장) top_down_150 시점 SSIM 0.96712 < 0.98. 원인은 양자화가 아니라 점 순서 재배치다 — 래스터 기준 구현이 깊이 동률일 때 번호가 작은 점을 이기게 하므로 모턴 순 재배치로 승자가 바뀐다(양자화만 0.9992, 순서만 0.9444, codec 0.9671). 기준(0.98)은 낮추지 않았고 해당 단언은 todo 로 남겼다. 감독 판정 필요: 래스터러 동률 규칙을 순서 무관으로 둘지, 비교 기준 이미지를 같은 순서로 렌더할지, 시점 제외 여부.
- 퍼징(T09.8)이 서버·클라이언트 불일치 3건을 찾았고 수정했다(아래 '수정').

## 수정 (T09.8 퍼징이 찾은 불일치)
클라이언트 할당 증폭(n 비례 6n B 를 스트림 검사 전에 할당), 서버 decodeChunk 의 헤더 의미 검사 누락(quantExp·tileSizeM), 클라이언트의 범위 부호 끝 상태(code ≠ 0)·비최소 LEB128 수용을 고쳤다. 수정 뒤 10만 회 퍼징: 서버·클라이언트 수용/거부 불일치 0, 4 MiB 초과 할당 0(호출당 최대 13,455 B), 최대 호출 시간 약 6 ms, 둘 다 정상 반환 6,931건 점 집합 일치, 체크섬 재계산 변이 88,464건. 서버·클라이언트가 의미 검사를 각자 복제하므로 한쪽만 바꾸면 어긋날 수 있다(퍼저가 잡는다).

## PR #36 반려 보정 (T09.F)
감독 반려(F-168 높음, F-169·F-170·F-171 중간, F-172 낮음)를 같은 브랜치에서 고쳤다. 서브에이전트 11개(sonnet 6·haiku 5, 승격 없음).
- F-168: encodeChunk 가 codec 0 입력의 길이·체크섬·헤더 의미를 검사한다. 감독 재현 ①②③ 을 직접 다시 돌려 모두 throw(끝 3 B 자름 → CodecError length, 체크섬 틀림 → checksum, lod=9 → AssetFormatError field). 정상 입력은 왕복 통과.
- F-169: 서버 decodeChunk 도 계약 streamRawBounds(n)(서버·클라이언트 공용 상수)로 rawLen 을 할당 전에 거부('limit').
- F-170(결정 0028): 기준 렌더를 codec 실제 순열로 재배열한 원본으로 그린다. todo 0. 8시점 최솟값: flat_boxes 0.99496/0.99299, terrain 0.99273/0.99129, holes 0.99826/0.99802(무손실/lossy 색). 순서 정렬 없이는 holes top_down_150 0.9671(진단).
- F-171: lossy 벤치가 실제 QUANT2 를 쓰고, pointMultiset 실제 비교, 벤치 정규식 단언 실행, 손상 시험이 CRC 재계산 후 지정 코드로 걸림, 경계값 시험.
- F-172: 서버·클라이언트 오류 코드 일치('stream'), 위치 LEB 비최소 거부, mode 1 비정규 컨테이너 거부, 색 입력 형식 검사, 계약을 단일 출처로 정리, decodeChunkInfo·colorMode 노출, 파일 복사 제거 등. F-172 ⑪ 시험 문턱은 낮추지 않고 '회귀 감시' 표시. ⑮ 소유 경로 밖 변경(ASSET_FORMAT·README)은 감독 승인 사항으로 기록만.
- 검증: `npm test` 2734 시험, 통과 2722, 실패 0, 건너뜀 12(기존), todo 0. 서브에이전트의 변이 결과는 보고된 것이며 내가 재실행하지 않았다(F-168 재현 ①②③ 만 직접).
- 주의: 한 서브에이전트가 공용 /tmp 백업 파일을 써서 구현 파일이 잠시 섞였다고 보고했고 git checkout 으로 되돌렸다. 최종 병합 뒤 전체 시험이 통과함을 확인했다.
- 미반영: F-173(T12.5), F-172 ⑪ 근거 있는 값 치환(표시만), 색 모드 검사 한 줄의 동등 변이 1건.
