# T13b 압축 한도 — 실험 노트 (S6: 구간당 ≤ 3,000,000 B)

- 제품 저장소는 읽기·측정만 했다: 작업 트리(브랜치 feat/t13b--8), HEAD 14ba5f4e. 제품 파일 변경 없음.
- 측정 스크립트: experiments/t13b-codec-measure.mjs (제품 코드는 제품 작업 트리 루트 기준 상대 경로로 import). node v22.22.0, 4코어 컨테이너.
- 단위: 1 MB = 10^6 B. "B/점" 은 본문+헤더 포함 바이트 ÷ 점 수.

## 질문
점 수를 줄이지 않고 압축률 개선(무손실 부호기 개선 + S9 를 해치지 않는 손실 양자화)만으로 구간당 바이트를 어디까지 내릴 수 있나. 목표 1.2 B/점(250만 점 × 1.2 = 3 MB)이 현실적인가.

## 방법
- 장면: fixtures/scenes/levels 구간 0(50 m × 100 m 띠, 기복 ±2 m), 시드 1. 최고 수준 N 점, 낮은 수준 N/2·N/4·N/8(낮은 수준은 최고 수준의 부분집합, 교체 방식). 4수준 합 = 1.875 N 점.
- 조각화: 장면은 y-up 이라 ENU(e = x, n = −z, u = y)로 바꿔 groupByTile → packChunk(codec 0) → encodeChunk(codec 1). 구간 0 은 64 m 타일 2개, 두 조각 모두 quant_exp 10(1/1024 m).
- 대안 부호기 길이는 "적응형 빈도 모델의 이상적 산술 부호 길이"(문맥별 빈도 표, 초기 1·증가 24·합 2^16 넘으면 절반)로 계산했다. 실제 산술 부호기는 이 길이 + 스트림당 수 바이트다. 복호 속도는 재지 않았다.
- 화질: server/raster_ref/zbuffer renderPoints + shade/shadeResult(램버트, 광원 [0.4, 0.8, 0.45], ambient 0.3, 클라이언트 셰이더와 같은 식) + server/metrics/ssim. 기준 = 양자화 전 f32 원본 렌더, 비교 = 같은 점 순서에서 필드만 양자화한 점군 렌더(순서 차이 없음). 8시점 최소값으로 판정(S9: ≥ 0.95).
  - 설정 A: 320×180, 점 지름 0.75 m(제품 server/codec/quality 와 같은 해상도·점 크기), 시점 8개는 띠에 맞게 거리 6~25 m, fov 60.
  - 설정 B: 640×360, 점 지름 0.08 m(N = 250만에서 평균 점 간격 약 4.5 cm 의 약 2배), 시점 8개 거리 2~15 m, fov 60.
- "어려운 변형"(hard): 같은 장면에 u 정규 잡음 σ = 1 cm, 색 채널별 독립 균일 잡음 −8..7, 법선 성분별 정규 잡음 σ = 0.08(약 5°)을 넣은 것. 실자산 대용이 아니라 합성 장면이 쉬운 쪽을 보정하는 괄호값이다.

## 재현 명령
```
cd experiments   # 연구 저장소 루트 기준
node t13b-codec-measure.mjs bytes  2500000                   # 현재 codec 1 필드별 (약 13 s)
node --max-old-space-size=8000 t13b-codec-measure.mjs alt 2500000   # 대안 부호기 (약 87 s)
node --max-old-space-size=6000 t13b-codec-measure.mjs hard 2500000  # 어려운 변형 (약 46 s)
node --max-old-space-size=6000 t13b-codec-measure.mjs ssim 2500000 1 A,B          # 손실 변형 0~16 SSIM (약 5 분)
node --max-old-space-size=6000 t13b-codec-measure.mjs ssim 2500000 1 A,B 17       # 대조: ±0.05 mm 흔들림
node --max-old-space-size=6000 t13b-codec-measure.mjs ssim 2500000 1 A,B 0,1,2,3,4,5,17 smooth  # 색 잡음 제거 장면
node --max-old-space-size=6000 t13b-codec-measure.mjs ssim 2500000 1 A,B 18,19,20,21,22         # 필드 조합
node --max-old-space-size=8000 t13b-codec-measure.mjs floor 2500000                # 지표 바닥(독립 재샘플)
for n in 156250 312500 625000 1250000 2500000; do node t13b-codec-measure.mjs budget $n 1; node t13b-codec-measure.mjs budget $n 1 hard; done
```
결과는 결정적이다(시드 고정, 난수는 스크립트 안 고정 시드).

- 신뢰도: 형식 1(27 B, dense.ply 와 같은 x·y·z·법선·rgb)에는 신뢰도 필드가 없다(renderer_basis §7-4). 현재 0 B/점이며 측정 대상이 없다. .dmap 의 신뢰도 지도는 점 파일로 넘어오지 않는다.
- 구간 바이트(250만): codec 1 무손실 4수준 합 17,085,685 B(17.09 MB), 최고 수준만 8,598,432 B(8.60 MB).
- "현재 약 11 B/점" 은 codec 0 이다. 합성 장면에서 codec 1 은 이미 3.4~3.6 B/점이고, 어려운 변형에서는 6.25 B/점(아래 4절).
- 합성 색이 쉬운 이유: 장면 색은 (체크 2값 × 줄무늬 2값 × 공통 잡음 16값)이라 서로 다른 색이 256개 이하라서 PALETTE 모드가 선택된다(0.567 B/점). QUANT2(손실) 색은 DELTA 경로로 가므로 오히려 1.162 B/점으로 커진다.
- 점이 적을수록(성길수록) B/점이 커진다: 위치 키 차분이 커지기 때문(수준 0 3.28 → 수준 3 2.66).

해석(측정에서 바로 나오는 것만)
- 위치: S9(원본 렌더 대비 ≥ 0.95)를 문자 그대로 적용하면 현재 격자 1/1024 m 만 통과한다. 3.9 mm(현 형식이 허용하는 가장 거친 격자)부터 두 설정 모두 미달. 원인은 원판 렌더의 깊이 경쟁이다: 거의 평평한 면을 수직으로 내려다보면 한 픽셀을 덮는 원판들의 깊이 차가 mm 이하라 위치를 조금만 옮겨도 이기는 점과 원판 가장자리 덮임이 바뀐다. 색 잡음을 없애도(smooth) 거의 같으므로 색 잡음 탓이 아니다.
- 이 지표는 "같은 점인가" 를 잰다: 똑같이 타당한 독립 재샘플이 0.81 / 0.13 이므로, 3.9 mm 양자화(0.85 / 0.90)는 재샘플보다 원본에 더 가깝지만 0.95 는 못 넘는다. 위치 양자화 한도는 화질 자체보다 S9 의 정의(기준 = 같은 원본 점의 렌더)가 정한다.
- 250만 점에서는 현재 codec 1 자체가 설정 A top_down 0.956 으로 S9 문턱에 가깝다. 제품 server/codec/quality 의 문턱 0.98(QUALITY_MIN_SSIM)로 보면 이 시점·점 수에서는 현재 codec 1 도 미달이다(제품 시험은 20만 점·다른 시점이라 직접 비교는 아님).
- 색: 단독으로는 4비트까지 통과, 위치 1/1024 m 와 조합하면 5비트까지(4비트 + PCA 는 A 0.939 로 미달).
- 법선: oct4 까지 통과하고, 미전송 후 클라이언트 추정이 oct8 보다도 원본에 가깝다(합성 법선은 해석적 매끈한 면이라 추정이 쉬움).

## 5. 구간 바이트와 3 MB 점 예산 (budget)
방식(모두 조각당 헤더+고정+컨테이너 174 B 포함)
- S0: 현재 codec 1 무손실(실제 encodeChunk).
- S1: 같은 화질 무손실 개선 — 위치 8분 트리 6이웃(1/1024 m) + 법선 oct8 문맥 적응형 + 색 min(현재, 채널 간 잔차 8비트).
- S2: S9 문자 그대로 통과하는 가장 작은 조합 — 위치 8분 트리(1/1024 m) + 색 5비트 채널 간 잔차 + 법선 미전송(클라이언트 추정). SSIM A 0.952 / B 0.969(3절, N = 250만에서만 확인).

## 결론(측정 범위 안)
- 무손실 부호기 개선 여지: 같은 화질에서 약 8~12%(S0 → S1: 합성 3.44 → 3.03, 어려운 6.25 → 5.75 B/점, 최고 수준). 위치는 8분 트리로 −14%(2.66 → 2.29), 색은 합성에서 이미 PALETTE 가 brotli 수준이고 어려운 변형에서 −7%, 법선 −1~16%.
- 1/1024 m 위치는 어떤 부호기로도 이론 하한 1.56 B/점(250만 점, 50 × 100 m, 높이 잡음 0) 아래로 갈 수 없다. 목표 1.2 B/점(최고 수준만 기준)이나 0.64 B/점(4수준 합 기준: 3 MB ÷ 468.75만 점)은 위치만으로도 넘는다.
- S9 를 지키는 범위의 손실 양자화(색 5비트, 법선 미전송·클라이언트 추정)를 더한 최선(S2): 구간당 250만 점 기준 최고 수준만 6.3 MB(합성) ~ 8.2 MB(어려운), 4수준 합 12.6 ~ 16.0 MB. 압축만으로는 3 MB 에 닿지 않는다.
- 3 MB 를 맞추려면 S2 로도 최고 수준 점 수를 구간당 약 41만~51만(4수준 합 기준, 전송 76만~95만 점) 또는 84만~108만(최고 수준만 기준)으로 줄여야 한다. 현재 codec 1 이면 22만~36만(4수준 합) / 44만~77만(최고 수준만).
- 위치를 15.6 mm 로 거칠게 하면(S3) 합성 최고 수준만 2.6 MB 로 3 MB 안에 들지만, S9(원본 렌더 대비)를 크게 밑돈다(A 0.66 / B 0.71). 이 길은 S9 의 기준 정의와 묶여 있다(3절 대조: 독립 재샘플도 0.81 / 0.13).

## 한계 — 합성 장면이 실제보다 쉬운 점 / 어려운 점
쉬운 점
- 색: 서로 다른 색 ≤ 256(PALETTE 적용), 잡음이 세 채널 공통. 실제 사진 색은 채널 독립 잡음·복잡한 무늬가 있어 어려운 변형처럼 2 B/점 안팎일 가능성이 크다(실자산 미측정, [local]).
- 법선: 해석적 매끈한 면(기복 ±2 m)이라 0.21 B/점이고 클라이언트 추정이 쉽다. MVS 법선은 잡음이 있어 1.4 B/점(약 5° 잡음 변형) 쪽에 가깝고, 실제 장면(건물 모서리·벽)에서는 추정 법선의 화질 영향이 클 수 있다. PCA 추정은 +y 로 방향을 고정했는데 실제는 카메라 쪽 방향 정하기가 필요하다. 클라이언트 추정 계산 시간은 재지 않았다.
- 형상: 단층 2.5D 지면, 고른 밀도, 이상점·가림·건물 없음. 법선 정보 0(전부 위)도 SSIM 0.99 이상이라 법선 양자화 한도는 실제 장면에서 더 빡빡할 수 있다.
- 수준: 합성의 낮은 수준은 최고 수준의 부분집합이다. 실제 4수준(250·1000·3500·7000 스텝)은 서로 다른 결과물이라 부분집합 성질을 쓰는 누적 부호는 실제에 바로 적용할 수 없다(이번 표는 교체 방식 그대로 합산).
어려운 점
- 위치: 점이 면 위 i.i.d. 균일 무작위라 정보량이 최대다. 실제 MVS 점은 픽셀 격자에서 나와 더 규칙적일 수 있어 위치가 더 잘 줄 가능성이 있다(미측정).
- 화질 지표: 큰 원판 + 거의 평평한 면 + 수직 시점에서 깊이 경쟁이 mm 단위로 갈려 위치 양자화에 매우 민감하다. 실제 장면은 기복·건물로 깊이 차가 커서 덜 민감할 수 있다.
기타
- 대안 부호기 길이는 이상적 적응형 부호 길이(구현·복호 속도 미검증). 어려운 변형의 손실 조합 SSIM, N < 250만에서의 SSIM 은 재지 않았다(점 예산 표의 S2 화질은 250만 점에서만 확인).
- 시드 1 하나, 구간 0 하나. 설정 A·B 의 시점은 이 노트에서 정한 것이며 S9 의 고정 시점 8곳(실자산 viewpoints)과 다르다.
