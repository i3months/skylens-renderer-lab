# T15.3b F-408 ⑦ 건물 층 성능 (결과 버퍼 재사용 + 묶음 컬링)

## 바꾼 것 (client/tower/buildings/)
- `render(camera, out?)`: out 을 주면 지우고(color 0, depth 0, index −1) 같은 객체를 돌려준다. 크기·형식이 다르면 RangeError. 주지 않으면 이전처럼 새로 만든다. render 경로에는 합성 보조 버퍼가 없다(합성은 `composeLayers`). `composeLayers(base, over, into?)` 에 선택 인자 `into` 를 추가해 합성 결과 버퍼도 재사용할 수 있게 했다(base·over 와 배열을 공유하면 던진다).
- 묶음 컬링: accept 때 묶음별 ENU 경계상자(정점·선 끝점·표본점 전부)를 한 번 계산한다. render 에서 모서리 8개를 카메라 공간으로 옮겨 근·좌·우·상·하 평면 중 하나의 바깥에 8개가 전부 있으면 뺀다(가장자리 2 화소 여유, 보수적). 빠진 자리에는 빈 묶음(공유 상수)을 넣어 래스터에 넘기므로 `out.index` 의 묶음 번호는 그대로다. 래스터 파일은 건드리지 않았다.
- 시험·진단용 추가: 생성 옵션 `cull:false`(컬링 끄기), `layer.stats()` → `{groupsTotal, groupsDrawn}`. 계약(buildings.mjs)에 render 의 out 재사용 정의를 추가했다. composeLayers 의 into 는 계약 밖이다(필요하면 계약에 올릴지 정해 달라).
- 유한성: `validate.mjs` 가 positions·edgeLines·points 를 accept 때 이미 검사한다. index.mjs 의 render 경로에는 정점별 isFinite 가 없다(추가하지 않았다). 래스터 안의 정점별 검사는 그대로다(아래 한계).

## 측정 [cloud] (1280×720, 3000동, 100묶음, 중앙값 11회, CI 컨테이너 CPU, node)
장면은 `reuse_cull.test.mjs` 의 합성 도시(60×50 격자, 동 간격 50 m, 6×5동씩 묶음). 전 = HEAD 의 index.mjs(매 프레임 새 버퍼, 컬링 없음), 후 = 이번 변경(out 재사용 + 컬링).

| 옵션 | 카메라 | 전 ms | 후 ms |
|---|---|---|---|
| points | 도시 전체 | 7.6 | 3.1 |
| points | 도시 1/10(모서리) | 4.0 | 1.2 |
| black | 도시 전체 | 26.9 | 33.6 |
| black | 도시 1/10(모서리, 12/100 묶음) | 11.7 | 3.5 |
| black | 900 m 확대(면적 1/10) | 30.9 | 18.5 |
| aerial | 도시 전체 | 30.2 | 26.2 |
| aerial | 도시 1/10(모서리) | 9.1 | 3.4 |
| aerial | 900 m 확대 | 37.8 | 33.5 |

시험 ③ 은 black 도시 전체 약 33 ms 대 1/10 약 4 ms(묶음 12/100 ≤ 33)를 단언한다(≤ 1/3). 컬링 효과는 묶음 분할(서버 묶음 크기)에 달렸고 perf.test.mjs 합성 번들은 1묶음이라 컬링 무효(1묶음 edge 시점 켬 11.4 대 끔 9.4 ms).

## S1(33 ms)과의 관계
- 전체 시점 약 30~35 ms 로 S1 경계, 비스듬 시점은 64~73 ms 로 초과(CPU 경로, 실기기는 [local]). 이 장면에서는 도시 전체를 보는 black/aerial 이 이미 30~35 ms 라 S1 의 33 ms 근처인데 여유가 작다(CPU 잡음 이내). 과제에 적힌 41~112 ms 는 이 장면에서는 재현되지 않았다. perf.test.mjs 의 장면은 3000동이 한 묶음이라(묶음 컬링 대상이 1개) 거기서는 컬링이 아무것도 못 빼고, 이번 변경의 이득은 결과 버퍼 재할당 제거뿐이다. 묶음 컬링은 서버가 건물을 공간 타일로 묶어 줄 때만 효과가 있다(공간 묶음 구성은 이 작업 밖, 서버/자산 쪽 확인 필요).
- 컬링은 화면 밖 묶음의 삼각형·선 준비 비용을 없앨 뿐 화소 채우기 비용은 줄이지 않는다. 가까이 확대한 장면(900 m)은 18~34 ms 로 채우기가 지배하며 컬링 이득이 작다(30.9 → 18.5 는 컬링 + 버퍼 재사용 합).

## 한계·보고
- black 모드의 `lines.mjs` lineMark(약 0.9 MB)는 통합 단계에서 모듈 수준 재사용 버퍼로 바꿨다(호출마다 fill(0)). 시험 ① 의 ArrayBuffer 증가 단언은 points·aerial 에만 있고 black 은 out 의 `===` 만 본다 — black 의 ArrayBuffer 단언은 미추가.
- 래스터 안에 정점·끝점·표본점별 `Number.isFinite`(points.mjs:40, lines.mjs:67, raster_flat.mjs:127)가 남아 있다. accept 의 validate 가 이미 보장하므로 중복이지만 래스터 단독 호출 방어로 남겨 둔다. 소유자에게 제거 여부를 넘긴다(안 고침).
- lines.mjs 는 선분마다 작은 배열(`pq`)을 만든다(GC 압력). 같은 소유자 몫.
- 컬링은 묶음 경계상자 단위라 한 묶음이 도시 전체를 덮으면 못 뺀다.
- 남은 병목은 raster_flat rasterSub 64.6%(비스듬 black 64~73 ms)로 T17 [local] 성능 판단 때 다룬다.
- 실기기 fps 는 [local]. 위 ms 는 CI 컨테이너 CPU 값이다.
