## 발견과 이탈 (renderer_basis §7-4 관련)

1. **데모 자산은 27 B/점이 아니다.** 모든 구간 파일은 PLY 바이너리 14 float32(`x y z f_dc_0..2 opacity scale_0..2 rot_0..3`, 3D 가우시안 스플랫 배치) = **56 B/점**이다. 파일 크기는 헤더 + 56×점 수와 정확히 일치한다(16개 구간 파일, 4개 light 파일). T01.3 의 "27 B × 점 수와의 차 ≤ 헤더" 기준은 이 자산에 적용할 수 없어 실패로 기록한다(`assets.format.assumed_stride_matches = 0`). 27 B 점 형식은 renderer_basis 의 원본 점군 규약이고 skylens 의 스플랫 자산은 다른 형식이다. 경량 자산 포맷(T03)의 입력이 무엇인지 감독이 정해야 한다.
2. 데모 구간 총 41.97 MB(전 수준 합)이며 SPEC 의 "구간당 약 67 MB" 는 실데이터 기준이라 T01.12 [local] 로 확인한다.
3. 기준 영상(T01.8)은 스플랫의 불투명도·크기·회전을 무시하고 중심점만 그렸다. 지표 기준 영상으로는 임시이며 T06 에서 대체한다.

## 미달

- **T01.5 완료 기준(건물 수 6,191 ± 1 % 재현) 미달.** skylens 저장소에 건물 데이터·녹화 응답이 없다(6,191 은 문서 글에만 있음). 실제 건물은 VWorld WFS(`lt_c_bldginfo`, 키 필요)에서 라이브로 받는다. 오프라인 대체 생성기(`synthesizeBuildings`)를 옮겨 쟀더니 415동이다. 테스트는 이 415 를 단언한다. 6,191 을 재현하려면 대전 bbox 의 VWorld 응답 녹화 파일이 필요하다(사람이 키로 한 번 받아 주면 됨). 지형·영상 타일 응답 바이트도 같은 이유로 포함되지 않았다. 키 사용 시 요청 수 계획은 100개(정적 모델, 측정 아님).
- T01.4 의 웹소켓 녹화는 합성이다.
- 번들 크기·첫 프레임·힙은 모두 vite 프로덕션 빌드가 아닌 근사다. 기준 기기 실측(T01.11)이 확정값이다.

### 새 발견·결정 요청

1. **앵커(F-010)**: 점군 쪽 앵커 출처를 찾지 못했다. PLY 헤더·스플랫 레코드에 없고 skylens 의 SplatAlign.anchor 는 웹소켓 청크 메시지로만 온다. 그래서 앵커는 "운영자 선언값, 점군 대조 없음"이며 계약 주석을 그렇게 고쳤다. tower 시점 앵커는 사람 확인이 필요하다.
2. **자산 형식 사실(T03·T04·T08 입력 결정 근거)**: 56 B 자산에는 법선이 없다. opacity 는 신뢰도가 아니다. step 수준(250/1000/3500/7000)은 Δd 해상도 LOD 와 무관하다(점 개수 단계다).
3. 제품 저장소에 skylens `develop` 가 없고 `main` 만 있다는 보고가 있었다(서브에이전트 2건). 연구 문서의 `develop` 기준과 불일치하므로 사람이 확인해 달라. 상황판 3D 캔버스는 `recon.html` 의 `#view2`, 앱 씬 변환은 `src/skylens_client/data/sceneSource.ts:54,226-297` 에서 확인했다(감독 인용 경로 sceneSource.ts:350-385 는 못 찾음).
4. TASKS T01.3 의 27 B 기준 문구는 위 판정과 어긋나므로 감독이 문구를 정정해 달라.
