# T02.7 3D 타일·LOD 표준 사례 (지형·건물·점군)

조사 문서. 코드 아님. 근거 위계: SPEC §2(깊이 해상도 Δd ≈ d²/(f·b), renderer_basis §3-7·§9), RULES §1(4수준 교체, 도착한 것만 그림, ENU 1 unit = 1 m).
조사 환경 제약: 아래 URL 중 `advances.realtimerendering.com` 은 네트워크 차단으로 열람하지 못했다. 그 항목은 기억 기반이며 "미확인"으로 표시한다.

## 0. 우리 쪽 요구 요약

- 타일 = ENU 사각 격자(T03.2 `tile_index`). 시간축 단위 = 구간, 정밀도 축 = 딜레이 패턴 4수준(250/1,000/3,500/7,000 스텝).
- 새 수준은 같은 구간의 낮은 수준을 교체(누적 금지). 추월당한 수준은 건너뛴다. 도착한 것만 그린다.
- 점 밀도 근거: 먼 곳은 깊이 정밀도가 거리 제곱으로 나빠진다(Δd ≈ d²/(f·b)). 즉 먼 곳의 점은 원래 부정확하므로 성기게 보내도 손실이 작다.
- 관제탑에는 DEM 지형 + 건물 약 6,191동도 있다(지형·건물 사례가 필요한 이유).

## 2. 사례별 상세

### 2-1. OGC 3D Tiles
- 구조: tileset JSON 에 `asset`, `geometricError`, `root`. 각 타일은 경계 부피(box/sphere/region), `geometricError`, content URI, 선택적 변환, children, `refine`(상속 가능). 타일 포맷은 glTF 2.0 이 기본.
- refinement
  - REPLACE: 세분화되면 부모는 그려지지 않고 자식이 대신 그려진다.
  - ADD: 부모를 그리면서 자식도 함께 그린다.
- 선택: 명세는 "타일을 그리고 자식을 그리지 않을 때 생기는 오차(m)"를 geometricError 로 두고, 클라이언트가 거리·화면 크기·해상도와 합쳐 SSE(픽셀)를 계산해, 허용 최대 SSE 를 넘으면 세분화한다고 규정한다. 즉 기준은 화면공간 오차이고 거리는 SSE 계산의 한 입력이다. 정확한 SSE 식은 구현 자유(명세 문장 기준).
- 암묵 타일링: 쿼드트리/옥트리를 경계 부피 나열 없이 템플릿 URI + 가용성 비트로 표현. 좌표로 임의 접근 가능.
- 우리와의 대응
  - ADD ↔ 누적, REPLACE ↔ 수준 교체. 우리 규칙 "같은 구간의 낮은 수준을 교체, 누적 금지"는 REPLACE 와 같은 의미다. 다만 ADD 형 점군(조각이 서로 겹치지 않는 부분집합)은 대역폭을 아낄 수 있어 수준 교체에서 "증분 조각"을 쓸지는 T03 에서 따로 정할 문제(미결).
  - geometricError(m) ↔ 우리가 수준별로 기록할 "ENU 최대 복원 오차(m)". 같은 단위(m)라 SSE 식으로 바로 이어진다.
  - 3D Tiles 는 지구 중심 좌표 + 임의 변환을 쓰지만 우리는 ENU 격자만 쓰므로, 암묵 타일링의 쿼드트리 인덱스를 격자 (i,j,level)로 단순화할 수 있다.
- 출처
  - https://github.com/CesiumGS/3d-tiles/tree/main/specification
  - https://raw.githubusercontent.com/CesiumGS/3d-tiles/main/specification/README.adoc (HLOD·SSE·geometricError 문장)

### 2-2. CesiumJS (3D Tiles 구현)
- 라이선스: Apache-2.0(LICENSE.md 첫 줄 확인). 상용·비상용 모두 가능. 코드 차용 시 NOTICE·고지 필요.
- 선택: 타일 순회 중 SSE 가 허용치를 넘으면 자식으로 내려가고, 자식이 아직 로딩 중이면 부모를 계속 그리는 방식(기억, 구현 세부 미확인).
- 우리와의 대응: "도착한 것만 그린다"와 일치. 단 로딩 중 부모를 유지하는 것은 우리 규칙의 "낮은 수준 유지 후 교체"와 같다.
- 차용: 전체 엔진은 WebGL 지구본 전체라 번들 ≤ 300 KB(S4)에 맞지 않는다. 타일 순회·SSE 식 부분을 읽고 직접 구현하는 것이 현실적. 코드 복사 시 Apache-2.0 고지.
- 출처: https://github.com/CesiumGS/cesium

### 2-3. 지형 쿼드트리 — quantized-mesh
- 타일링: 레벨 0 에서 시작해 레벨마다 4 분할하는 쿼드트리(TMS 기본, EPSG:4326 또는 3857).
- 양자화: 정점 u, v, 높이를 16비트 부호 없는 정수(0~32767)로 타일 안 상대 위치·최소~최대 높이에 맞춰 저장. 델타 + 지그재그 부호화로 압축. 확장으로 법선·물 마스크.
- LOD 선택: 명세는 LOD 규칙을 정의하지 않는다(확인). 소비자가 레벨별 오차를 정한다(Cesium 은 레벨별 최대 기하 오차 사용, 세부 미확인).
- 우리와의 대응
  - ENU 사각 격자 타일 = 쿼드트리 한 레벨. DEM 관제탑 지형은 이 방식을 그대로 흉내 낼 수 있다(격자 원점·간격은 RULES §1 대로 ENU m).
  - 타일 경계에서 균열이 생기지 않도록 이웃 레벨의 경계 정점 일치가 필요(스커트 또는 경계 고정). 구체 방법은 미확인.
  - 16비트 양자화: 타일 크기 L(m)이면 단계 L/32767. 예 L = 512 m → 약 1.6 cm. 우리 "최대 복원 오차 명시" 요구와 맞는다.
- 출처: https://github.com/CesiumGS/quantized-mesh

### 2-4. I3S (Esri, OGC 커뮤니티 표준)
- 라이선스: 저장소 안내상 CC BY-ND 4.0. 표준을 구현해 서비스·클라이언트를 만드는 것은 자유이나 수정본 재배포 금지.
- 구조: 3D 객체, 통합 메시, 점, 점군, 건물 장면 레이어. 노드 트리를 노드 페이지로 스트리밍. LOD 지표 필드(`lodSelection`, 화면 임계 등)는 이번 열람에서 확인하지 못했다(미확인).
- 우리와의 대응: 건물 레이어는 관제탑 건물 6,191동과 가장 가깝다. 단 세부는 미확인이라 대응표를 채우지 못한다.
- 차용: 문서 열람 후 아이디어 참고만. 문서·스키마 복제·수정 금지.
- 출처: https://github.com/Esri/i3s-spec

### 2-5. Potree 옥트리 점 LOD
- 점군을 옥트리로 나눠 노드마다 점 부분집합을 저장하고 가까운 곳·큰 노드부터 더 깊게 불러온다. 대용량(수십억 점) 대상. WebGL, three.js 기반(README 요지).
- 라이선스: Potree 본체 BSD-2-Clause 형식(저작권 고지 + 면책 조항 유지 조건, LICENSE 본문 확인). PotreeConverter 도 BSD-2-Clause 형식(조건 2개 확인). 본체 LICENSE 에는 포함 라이브러리 항목이 더 있을 수 있으나 전부 열람하지 못했다(미확인).
- LOD 기준: 노드의 화면 투영 크기와 점 예산. 세부 식은 이번에 열람하지 못했다(미확인).
- 우리와의 대응
  - 옥트리의 상위 노드 = 성긴 수준. 우리 4수준(250/1,000/3,500/7,000 스텝)은 시간(스텝) 축 LOD 이고 옥트리 깊이는 공간 축 LOD. 두 축이 직교하므로 "구간 × 수준 × 타일 × (선택) 공간 깊이"가 된다. 공간 깊이를 쓸지는 T03 결정.
  - 점 부분집합 방식(ADD 형)은 상위 점을 하위가 재사용하므로, 수준 교체와 달리 누적. RULES 의 "누적 금지"와 충돌하므로 그대로는 못 쓰고, 수준별 완전 대체 + 같은 점 ID 로 중복 제거하는 변형이 필요(미결).
  - 깊이 해상도 근거: 점 간격 s(d) 를 Δd(d) = d²/(f·b) 에 맞추면 먼 타일일수록 성기게 보내도 손실이 작다는 설계 논리와 직접 이어진다(§3).
- 출처: https://github.com/potree/potree , https://github.com/potree/PotreeConverter

### 2-6. Nanite 류 클러스터 계층
- 내용(기억, 이번에 열람 못 함 — 미확인): 메시를 작은 삼각형 클러스터로 쪼개고 클러스터 묶음을 단순화해 DAG 로 쌓은 뒤, 화면공간 오차가 임계 미만인 클러스터만 GPU 에서 골라 그린다. 클러스터 경계는 인접 LOD 와 균열이 없도록 고정.
- 열람 시도한 출처: https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf (차단)
- 우리와의 대응: 선택 단위가 타일이 아니라 클러스터라는 점이 다르다. 점군에서는 "점 N 개 클러스터" 로 바꿔 쓸 수 있으나 2단계(서버 GPU) 이후 주제다.
- 차용: 코드 차용 금지(비 MIT/Apache). 아이디어만.

## 3. 거리 대 화면공간 오차: 우리 근거와의 관계

- SSE 방식: 픽셀 오차 ρ ≈ g·H/(2·d·tan(fov/2)) (g = geometricError(m), H = 화면 높이 px). 같은 ρ 를 유지하면 허용 g 는 거리 d 에 비례한다(선형). 이 식은 일반적 투영 관계이며 명세가 특정 식을 요구하지는 않는다.
- 우리 데이터의 자체 오차: 깊이 불확실성 Δd ≈ d²/(f·b)(제곱). 즉 먼 곳일수록 원본 점이 이미 부정확하다.
- 따라서 두 기준이 요구하는 전환 거리가 다르다: SSE 기준 전환 거리는 g 에 비례(≈ g·H/(2ρ·tan(fov/2))), 정밀도 기준은 d ≈ √(g·f·b). 두 값을 함께 놓고 둘 중 더 먼 쪽에서 수준을 내리면 "눈에 보이는 손실 + 원래 부정확"을 둘 다 고려한 설계가 된다. (본 문서 추정. 실측 근거 없음 — T03/T04 실험에서 확인 필요.)
- 표준 사례는 모두 SSE(픽셀)를 1급 기준으로 쓴다. 거리 단독 기준은 해상도·화면 크기·FOV 를 무시하므로 사례가 쓰지 않는다. 우리도 SSE 를 기본으로 두고 거리 제곱 항은 g 의 사전 계산(수준별 geometricError 표)에 반영하는 쪽이 자연스럽다.

## 6. 잠정 의견

타일 구조는 3D Tiles 의 개념(타일 트리, REPLACE 세분화, geometricError(m) 기반 SSE 선택)을 아이디어로 가져오되, 우리는 지구 좌표가 필요 없으므로 ENU 사각 격자 (i, j, 구간, 수준) 색인으로 단순화하는 것이 낫다고 본다. 관제탑 DEM 은 quantized-mesh 식 16비트 상대 양자화(타일 크기 ÷ 32767)를 참고하고, 점군의 공간 LOD 는 Potree 옥트리를 참고하되 "누적 금지" 규칙과 충돌하므로 수준별 완전 교체 + 점 ID 중복 제거 같은 변형이 필요하다. 선택 기준은 SSE 를 기본으로 하고 거리 제곱 근거(Δd ≈ d²/(f·b))는 수준별 geometricError 표를 만들 때 반영한다. 코드는 CesiumJS(Apache-2.0)·Potree(BSD-2)만 고지하고 차용 후보로 두며, I3S·Nanite 는 아이디어로만 쓴다. 위 판단은 문헌 열람과 일부 기억에 근거한 잠정안이고, 수준별 오차 표와 전환 거리는 T03 이후 실측이 필요하다.
