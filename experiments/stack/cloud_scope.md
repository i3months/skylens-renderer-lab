# T02.10 GPU 없는 클라우드 세션에서 검증 가능한 범위

근거 문서: SPEC.md §4(성공 기준)·§4 측정 방법, TASKS.md(태그 정의와 T01~T24), ops/WORKER.md §1·§2.
조사 방식: 이 세션에서 직접 명령을 실행해 확인했다. 아래 "실측" 절의 값은 모두 이 세션에서 나온 것이다.

## 1. 이 세션에서 실제로 확인한 것

환경: Linux 6.18, CPU 4코어, 메모리 16 GB. 기록 시점 2026-10-01.

### 1.1 GPU·드라이버 계열

| 확인 | 명령 | 결과 |
|---|---|---|
| NVIDIA GPU | `nvidia-smi` | 명령 없음(`command not found`) |
| Vulkan | `vulkaninfo --summary` | 명령 없음. 시스템 Vulkan 도구·ICD 확인 불가 |
| DRM 장치 | `ls /dev/dri` | 디렉터리 없음 |

결론: 물리 GPU도 렌더 노드(`/dev/dri`)도 없다. 네이티브 GPU API(Vulkan·wgpu 등)로 하드웨어 가속 경로를 시험할 수 없다. TASKS 의 "클라우드 세션에는 GPU 가 없다"는 전제와 일치한다.

### 1.2 Chromium 헤드리스 (playwright 1.56.1, Chromium 141.0.7390.37, `/opt/pw-browsers` 의 기설치본만 사용, `playwright install` 안 함)

세 가지 실행 인자로 시험했다. 시험 방식은 `localhost` 를 가장한 페이지(보안 컨텍스트)에서 `getContext('webgl2')`, `navigator.gpu.requestAdapter()`, 그리고 200,000점 `gl.POINTS` 한 장 그리기 후 `readPixels` 를 해 보는 것이다.

| 실행 인자 | webgl2 | 렌더러 문자열 | WebGPU 어댑터 | WebGPU 장치 | 점 그리기 |
|---|---|---|---|---|---|
| 기본(인자 없음) | 가능 | ANGLE (Vulkan 1.3.0, SwiftShader Device (Subzero), SwiftShader driver) | `null`(없음) | - | 성공, 20만 점 약 1.9 s(셰이더 컴파일·초기화 포함) |
| `--use-angle=swiftshader --enable-unsafe-swiftshader` | 가능 | 위와 같음 | (WebGPU 인자 없이 `navigator.gpu` 만 노출됨) | - | (같은 경로) |
| `--enable-unsafe-webgpu --enable-features=Vulkan --use-angle=swiftshader --enable-unsafe-swiftshader` | 가능 | 위와 같음 | 있음: vendor `google`, architecture `swiftshader` | `requestDevice()` 성공 | 성공, 약 1.5 s |
| `--enable-unsafe-webgpu --enable-features=Vulkan --use-vulkan=swiftshader --use-webgpu-adapter=swiftshader --enable-unsafe-swiftshader` | 가능 | 위와 같음 | 있음(같음) | `requestDevice()` 성공 | 성공, 약 1.8 s |

보조 확인 값(webgl2): `MAX_TEXTURE_SIZE` 8192, `EXT_color_buffer_float` 사용 가능, webgl1 도 가능.

주의할 점:
- 보안 컨텍스트가 아닌 `about:blank` 에서는 `navigator.gpu` 가 `undefined` 다. WebGPU 시험은 `localhost`/https 출처에서 해야 한다. 처음 시험이 이것 때문에 "없음"으로 나왔고, 출처를 바꿔 정정했다.
- 기본 인자에서 WebGPU 어댑터는 `null`. 소프트웨어 WebGPU 는 `--enable-unsafe-webgpu` 와 SwiftShader 인자를 줘야 얻는다.
- 20만 점 시간은 한 번 잰 값이고 셰이더 컴파일·컨텍스트 생성 비용이 섞여 있다. 성능 수치가 아니라 "돌아간다"는 증거로만 쓴다. 점 4 px 크기여서 20만 점이면 화면이 거의 덮이므로(붉은 픽셀 약 26.2만/26.2만) 화질 판정 근거로 쓰지 않는다.

### 1.3 결론

- 소프트웨어 WebGL2: 가능(SwiftShader, 기본 설정에서 바로).
- 소프트웨어 WebGPU: 인자를 주면 어댑터·장치 획득 가능(SwiftShader Vulkan 위). 실제 컴퓨트·렌더 파이프라인 시험은 이번에 하지 않았다. 어댑터·장치 획득까지만 확인했으므로 WebGPU 셰이더 정합 시험을 계획에 넣기 전에 한 번 더 확인한다.
- 이 렌더링은 **CPU 위의 에뮬레이션**이다. 결과 픽셀의 기하·색 정합(투영, 깊이 우선, 셰이딩 수식)은 검증할 수 있으나, 속도·메모리·열·드라이버 차이·모바일 GPU 특성은 아무것도 말해 주지 않는다.
- 클라우드에서 쓸 수 있는 헤드리스 브라우저는 `/opt/pw-browsers` 의 chromium, chromium_headless_shell, ffmpeg 이다. (ffmpeg 는 소프트웨어 인코딩 정도만 가능하다고 보되, GPU 인코더 시험은 불가.)

## 2. 클라우드/로컬 판정 원칙

1. **정확성(무엇이 그려지는가)** 은 클라우드에서 된다. CPU 참조 래스터라이저(T06)가 renderer_basis §2 의 투영식을 직접 계산하고, 소프트웨어 GL 이 같은 장면을 그려 두 결과를 SSIM 으로 비교할 수 있다.
2. **크기(몇 바이트인가)** 는 클라우드에서 된다. 번들·자산·웹소켓 바이트는 결정적 수치이고 GPU 와 무관하다.
3. **속도·자원(얼마나 빨리, 얼마나 먹는가)** 은 로컬이다. SwiftShader 의 fps·지연·메모리는 기준 기기와 상관이 없다. 클라우드 값은 "참고값"이고 SPEC 기준 판정에 쓰지 않는다(SPEC §4 의 "합성 장면 기반 근사값").
4. **실데이터·사람의 눈·녹화** 는 로컬이다. 합성 장면은 실제 PLY 의 위아래 분포(F-027)나 실 VWorld 응답을 대신하지 못한다.
5. 클라우드 합성 수치로 SPEC 기준을 "통과"로 확정하지 않는다. 클라우드 통과는 "회귀 문턱·예비 확인", 확정은 [local].

## 5. 클라우드 세션에서 지켜야 할 표기 규칙

- 소프트웨어 렌더로 낸 시간·fps 는 반드시 "참고값(SwiftShader, CPU 4코어)"으로 적고 SPEC §4 기준 판정에 넣지 않는다.
- S9 를 클라우드에서 잴 때는 "합성 장면, 참조 래스터라이저 대비"를 명시한다. 실 GPU 래스터와의 차이는 열린 위험으로 남긴다.
- 헤드리스 시험 틀은 WebGPU 가 필요하면 보안 컨텍스트(localhost/https 출처)에서 실행하고 `--enable-unsafe-webgpu` 와 SwiftShader 인자를 명시한다. 이 인자 조합은 위 1.2 표에 있다.
- [local] 항목은 자동 주기 세션이 건너뛰고 STATUS `다음 할 일` 에 남긴다(WORKER §1-3).
- 서버 주소·계정·포트 등 비밀정보는 시험 기록에도 쓰지 않는다. 위 시험은 로컬 모의 출처만 사용했다.

## 6. T02 후보 조사에 주는 시사점

- 클라이언트 경량 래스터라이저(T02.4): WebGL2 는 클라우드 헤드리스에서 바로 검증되고, WebGPU 는 인자 필요·소프트웨어 어댑터만 가능하므로 CI 시험 가능성 면에서 WebGL2 가 유리하다. 이것은 검증 편의일 뿐 최종 결정 근거는 아니다(모바일 지원 범위·성능은 [local]).
- 서버 래스터라이저(T02.1·T02.2): 후보의 하드웨어 경로는 클라우드에서 시험 불가. 헤드리스 웹 GPU 계열은 SwiftShader 로 기능 시험이 되나 성능 근거가 못 된다. 후보 비교 표의 성능 칸은 "문헌·공식 자료 출처" 또는 "[local] 측정 대기"로 적어야 한다.
- 자산 처리 서버 런타임(T02.5): CPU 참조 구현과 테스트가 핵심 작업이므로 클라우드에서의 테스트 속도 비교가 의미가 있다.

## 7. 한계

- WebGPU 는 어댑터·장치 획득만 확인했고 실제 파이프라인(렌더·컴퓨트)과 SwiftShader 결과의 SSIM 은 시험하지 않았다.
- 20만 점 시간은 1회 측정이며 분산을 모른다. 성능 근거로 쓰지 않는다.
- 기준 기기 2종(SPEC §5)은 사람 확인 전 제안값이므로 [local] 항목의 구체 기기도 확정되지 않았다.
