# T16.21 — F-581·F-582 처리 노트

제품 브랜치 feat/t16-21 (feat/t16-20 병합 뒤 main 에서 땀).

## F-581 (중간)
- run.test.mjs: 늦은 쪽 상한 0.02→0.1 s, 이른 쪽(−2 ms)은 유지. 표본 간격 `tS[1]−tS[0]` 이 1 ± 0.05 s 인지 단언을 더했다(t0 어긋남은 이른 쪽과 간격으로 잡는다). 감독 보고의 부하 관측값은 +37~43 ms.
- clients.test.mjs: handshake 하한 HANDSHAKE_MS−5 유지, 상한 +150(감독 20:55 보강 후 값). 주석 근거를 부하 관측값으로 갱신.
- 부하 조건(소켓 시험 3개 병렬 + `yes` 2개) 반복 결과는 아래 '검증'.

## F-582 (낮음)
- ① socket/contract.mjs 의 runScenario 호출 줄에 method: SOCKET_METHOD 를 적어 run.mjs 와 맞춤.
- ② run_all/run.mjs: 클라우드 근사 방식 분기를 비어 있지 않은 thresholds 객체에만 적용. 빈 {} 는 else 로 가서 두 방식 모두 'thresholds object must not be empty' 로 던진다. 시험 report_path.test.mjs 추가.
- ③ tickOnRealClock 이 잘못된 durationS 에 동기 throw 대신 Promise.reject(RangeError). run_notes.test.mjs 를 rejects 로 바꿈.
- 모델: 서브에이전트 없이 작업자가 직접 처리(변경이 세 파일 안팎의 작은 수정), 승격 0.

- 소켓 시험 3개 병렬 + `yes` 2개 조건에서 run.test.mjs·clients.test.mjs·server_proc.test.mjs 묶음 10회: 실패 0.
