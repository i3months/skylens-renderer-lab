## 만든 것 (bench/load/socket/)
- server_main.mjs·server_proc.mjs: 자식 프로세스로 제품 server/ws createWsServer 를 띄움(포트는 OS 가 정함, 접속마다 4수준 페이로드 2048·8192·32768·131072 B 를 수준 순서로 전송). 제품 wire 프로토콜 전체가 아니라 bench 핸들러다.
- ws_client.mjs·clients.mjs: RFC 6455 최소 클라이언트, 30 연결 동시, connect/bytes/level/first_frame/close 이벤트(실제 ms).
- proc_stats.mjs: /proc/<pid>/stat·statm 로 서버 프로세스 CPU·RSS, 실제 시계 1초 표본(source server-process).
- run.mjs: 위를 묶어 runScenario(주입 로그)·checkServerSamples(실제 표본)·loadReport. 경로 마지막 시각을 min(30, durationS) 로 줄임(validateScenario 가 durationS 뒤 경로를 거절).

## 정리 항목
- F-559: server_stats 시험에 want=1·마지막 간격·마지막 tS 경계·null 가드 정확 단언(변이 6종 모두 실패 확인), burst firstArrival 첫 도착 시험·제목 정정.
- F-561: load_report 섞인 source → 'cpu/rss source: unknown' 시험(:98 삭제 변이에서 실패), 약한 단언을 정확 배열로.
- F-562: 계약 harness.mjs 개수 검사 서술 분리, 0063 추가 절.
- F-563: ①②③ first_frame(주석·level 검증·형식 틀린 입력 위반), ④ 계약 문구, ⑤⑥ 0063 추가 절, ⑦ bandwidth 비유한 RangeError, ⑧ server_stats 비숫자 usage 건너뜀(NaN 숫자는 기존 F-530 시험 때문에 표본에 남겨 checkServerSamples 가 잡음), ⑨ 이 노트.
